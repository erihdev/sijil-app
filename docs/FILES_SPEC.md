# مواصفة المرفقات (رفع صور وملفات من جهاز المعلم) — سجلي

الملفات المعنية: `js/files.js` (المكوّن)، `v/index.html` (صفحة العرض العامة لأولياء الأمور)، وقواعد `files` و`filesidx` في `firestore.rules`.

## لماذا هذا التصميم
Cloud Storage for Firebase يحتاج خطة مدفوعة، والمشروع على الخطة المجانية. لذلك يُحفظ المرفق **داخل قاعدة البيانات نفسها بلا أي تكلفة**: بطاقة تعريف صغيرة للملف، ومحتواه مقسّم على «قطع» في مجموعة فرعية. هذا يرفع السقف من ملف واحد ≤ 700 كيلوبايت (حد المستند الواحد) إلى ملف حتى **6 ميجابايت** موزّع على قطع.

## نموذج البيانات
| المسار | المحتوى |
|---|---|
| `files/{id}` | `{ n: الاسم, t: النوع, sz: الحجم بالبايت, scope, ref, tid, tn, ts, nc: عدد القطع }` |
| `files/{id}/parts/{i}` | `{ d: نص base64 لا يتجاوز 700000 حرف }` — `i` رقم من 0 إلى `nc-1` |
| `filesidx/{tid}` | `{ list:[{id,n,t,sz,scope,ref,ts}], tn, ts }` فهرس خفيف لكل معلم |
| `filesidx/school` | الفهرس المشترك لملفات مكتبة المدرسة (يراها كل المعلمين) |

- `id` = معرّف قصير `^[a-z0-9]{4,12}$` (نفس `shortId` في التطبيق).
- `scope` من: `lesson` · `student` · `school` · `comm` · `profile`. و`ref` وصف الموضع: `{code?, wk?, cid?, si?, tid?}`.
- **القوائم تُقرأ من الفهرس فقط** فلا يُنزَّل أي محتوى لعرض قائمة؛ ولا تُقرأ القطع إلا عند فتح ملف بعينه.
- `700000` تقبل القسمة على 4، فكل قطعة base64 مكتملة بذاتها ويصحّ ضمّها بالتسلسل.
- ملف 6 ميجابايت ⇒ نص base64 نحو 8 ميجابايت ⇒ 12 قطعة، كل قطعة أقل من حدّ المستند (1 ميجابايت).

## الحدود والسلوك
| البند | القيمة |
|---|---|
| أكبر ملف يُقبل من الجهاز | 6 ميجابايت (وما تجاوزها يُرفض برسالة عربية واضحة) |
| ضغط الصور | عرض 1600 بكسل، صيغة WebP، جودة تتناقص 0.80 → 0.60 → 0.45 → 0.32 حتى ≤ 700 كيلوبايت، ثم عرض 1200 ثم 900 عند اللزوم |
| صورة يعجز المتصفح عن فكّها (HEIC) | تُرفع كما هي مقسّمة على قطع بدل رفضها |
| PDF والصوت | يُرفعان كما هما مقسّمين على قطع، بشريط تقدّم حقيقي (قطعة قطعة) وزر إلغاء |
| الإلغاء | يحذف القطع المرفوعة ولا يترك بطاقة ولا أثراً في الفهرس |
| الحصة الشهرية | 60 ملفاً لكل معلم، تُحسب من الفهرس بتاريخ الشهر الحالي، ويظهر العدّاد قبل الرفع وفي البطاقة |
| الحذف | بتأكيد صريح، ويحذف القطع كلها والبطاقة والفهرسين |

ترتيب الكتابة مقصود: **القطع أولاً، ثم البطاقة، ثم الفهرس**؛ فالرفع المقطوع لا يترك ملفاً ناقصاً ظاهراً في أي قائمة.

## المكوّن `window.SIJIL_FILES`
| الدالة | العمل |
|---|---|
| `attach(opts)` | نافذة الإرفاق: «📎 إرفاق ملف من جهازي» و«📷 التقاط صورة» (على الجوال)، ضغط، شريط تقدّم، إلغاء. `opts = {scope, ref, title, onDone}` وتُرجع وعداً بقائمة ما رُفع |
| `list(scope, ref)` | قائمة الملفات من الفهرس (بلا تنزيل محتوى) مرتّبة بالأحدث |
| `open(id)` | نافذة عرض: صورة أو PDF أو مشغّل صوت + «نافذة جديدة» + «مشاركة» + «حذف» |
| `remove(id)` | حذف بعد تأكيد |
| `waLink(id, phone?, note?)` | رابط واتساب يحمل رابط العرض العام `v/?f={id}` |
| `libraryCard(el, opts)` | بطاقة جاهزة (أزرار + عدّاد الحصة + قائمة) تُركَّب في أي حاوية، وتُرجع `{refresh}` |
| `quota()` | `{used, quota, left, total}` |
| `viewURL(id)` | رابط صفحة العرض العامة |

المكوّن مستقل: يحقن شكله بنفسه (أصناف `sjf-`) ولا يعتمد على `css/app.css`، ويفتح نافذته فوق نوافذ التطبيق (`z-index:100`) فلا يُغلق بطاقة الطالب المفتوحة تحته.

**في النسخة التجريبية** (بلا سحابة) يُحفظ كل ذلك بالبنية نفسها في مخزن المتصفح على الجهاز (IndexedDB باسم `sijil-files`)، فتعمل التجربة كاملة بلا إنترنت، وتفتح صفحة `v/` المرفق من الجهاز نفسه.

## صفحة العرض العامة `v/index.html?f={id}`
على نمط `w/index.html`: نفس تهيئة Firebase و App Check والمصادقة المجهولة، بلا تسجيل ولا تطبيق. تقرأ البطاقة، ثم تجمع القطع أربعاً أربعاً مع شريط تقدّم، ثم تعرض الصورة أو ملف PDF أو مشغّل الصوت، ومعها «فتح بالحجم الكامل» و«حفظ في جهازي». وإن غاب الملف عن السحابة بحثت عنه في مخزن الجهاز (النسخة التجريبية).

## قواعد الأمان المطلوبة
```
match /files/{id} {
  allow read: if signedIn();
  allow create, update: if signedIn() && id.matches('^[a-z0-9]{4,12}$') && stamped()
      && request.resource.data.n is string && request.resource.data.n.size() <= 120
      && request.resource.data.t is string && request.resource.data.t.size() <= 40
      && (request.resource.data.t == 'application/pdf'
          || request.resource.data.t.matches('^(image|audio)/[a-zA-Z0-9.+-]{1,24}$'))
      && request.resource.data.sz is int && request.resource.data.sz > 0
      && request.resource.data.sz <= 6291456
      && request.resource.data.nc is int && request.resource.data.nc >= 1 && request.resource.data.nc <= 16
      && request.resource.data.scope in ['lesson','student','school','comm','profile']
      && request.resource.data.keys().hasOnly(['n','t','sz','scope','ref','tid','tn','ts','nc']);
  allow delete: if signedIn();
  match /parts/{i} {
    allow read: if signedIn();
    allow create, update: if signedIn() && i.matches('^[0-9]{1,2}$')
        && request.resource.data.d is string && request.resource.data.d.size() <= 700000
        && request.resource.data.keys().hasOnly(['d']);
    allow delete: if signedIn();
  }
}
match /filesidx/{key} {
  allow read: if signedIn();
  allow create, update: if signedIn() && key.matches('^[A-Za-z0-9]{1,12}$') && stamped()
      && request.resource.data.list is list && request.resource.data.list.size() <= 400
      && request.resource.data.keys().hasOnly(['list','tn','ts']);
  allow delete: if false;
}
```
الحذف مسموح لأي جهاز مصادَق — كحال بقية بيانات المشروع التي لا هوية حقيقية للعميل فيها؛ والواجهة تحصره في صاحب الملف أو المدير وتطلب تأكيداً.

## أين يظهر (أفضل المواضع)
### المعلم
1. **الدرس والحصة الحية**: «📎 مرفقات الدرس» — صور السبورة، عرض PDF، ورقة إضافية.
2. **بطاقة الطالب**: «📎 أدلة وأعمال» — صورة عمل الطالب أو شهادة، تصل ولي الأمر رابطَ عرض في رسالة واتساب.
3. **سجل التواصل**: إشعار موقّع أو صورة مع المراسلة.
4. **بنك أوراق العمل**: «⬆️ ورقة من جهازي» حين لا تناسب الورقة التفاعلية.
### المدير
5. **⚙️ الإدارة → 🗂️ مكتبة المدرسة**: مستندات لكل المعلمين (الجدول الرسمي، الخطة، النماذج، التعاميم)، وتظهر للمعلمين في «المزيد».
6. **التعاميم والمهام**: مرفق مع كل تعميم.
7. **هوية المدرسة**: شعار المدرسة وختم المدير للشهادات.
8. **الزيارة الصفية** و**بطاقة المعلم**: صورة أو قرار أو تكليف.

## القبول (اختُبر فعلياً)
- صورة 4.1 ميجابايت → ضُغطت إلى 678 كيلوبايت بصيغة WebP بعرض 1600 في نحو ثانيتين، وحُفظت على قطعتين (نص base64 أطول من البيانات بالثلث، فصورة قرب الحد تحتاج قطعتين)، وظهرت في القائمة وفي رابط العرض العام.
- ملف PDF 3.2 ميجابايت → قُسِّم على **7 قطع** بشريط تقدّم حقيقي (0% ← 14% ← 29% … 100%)، وأُعيد تجميعه **مطابقاً بالبصمة** (SHA-256) في التطبيق وفي صفحة `v/`، وعُرض بصفحتيه في قارئ المتصفح.
- ملف 8 ميجابايت → رُفض برسالة «حجم الملف 8.0 ميجابايت، والحد الأعلى 6 ميجابايت. اضغط الملف أو أرسله رابطاً.» ولم يُكتب شيء.
- الإلغاء أثناء الرفع لا يترك قطعاً ولا بطاقة، والحذف يزيل القطع والبطاقة والفهرس، والحصة الشهرية تُعرض وتُحترم.
